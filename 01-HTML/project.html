About This Project

This page is intentionally built using HTML without CSS or JavaScript. The goal is to understand HTML structure, meaning, accessibility, and document organization before worrying about visual design or complex behavior.

The project brings together concepts such as semantic HTML, accessible forms, links, images, lists, tables, media, and validation.

My approach is simple: Understand the fundamentals before moving to frameworks.

What I Have Learned

HTML stands for HyperText Markup Language. It describes the structure and meaning of web documents.

A simple HTML element looks like this: 

<p>This is a paragraph.</p>

The browser parses HTML and builds a DOM — a Document Object Model.

Semantic HTML in This Project

This project intentionally uses meaningful HTML elements instead of putting everything inside generic containers.

  • <header> introduces a page or section.
  • <nav> contains major navigation.
  • <main> contains the primary page content.
  • <section> groups related content.
  • <article> contains self-contained content.
  • <aside> contains related secondary content.
  • <footer> contains footer information.

My First HTML Article

Published October 4, 2026

Learning HTML properly changed the way I look at websites. Instead of seeing a webpage as a collection of colors and buttons, I can now think about the document underneath it.

A good HTML document has a hierarchy. The elements describe what the content actually is.

The structure of a document matters because the browser, assistive technologies, and other systems need to understand the content.

My next step is to learn CSS so that I can style this structure without changing its meaning.

Learning Tip

Don't memorize hundreds of tags at once. Learn what a piece of content means and then choose the appropriate HTML element.

Why does this matter?

Semantic HTML improves the structure of the document and gives browsers, search engines, developers, and assistive technologies more useful information.

My HTML Mental Model

I think about a webpage as a document tree. 

Document
|
+-- html
    |
    +-- head
    |   +-- metadata
    |   +-- title
    |   +-- resource information
    |
    +-- body
        +-- header
        +-- nav
        +-- main
        |   +-- section
        |   +-- article
        |   +-- aside
        |   +-- forms
        |   +-- tables
        |   +-- media
        |
        +-- footer

The important lesson is not memorizing every tag. The important lesson is understanding what the content means and choosing the correct element for it.
